The general configuration allows you to fully customise the layout of the panels as well as the settings for the functionalities like automatically adding network edges or the design of the network nodes. Below, we provide the default configuration of Drugst.One, the settings when no argument is given for the specific parameters. Any of these parameters can be overwritten by passing it to the ‘config’ parameter.

Global configuration and snapshot settings

The config passed by the host page is the global configuration of the main network. When a saved task or view is opened, Drugst.One temporarily uses its stored settings instead. Internally, this active snapshot configuration is called analysisConfig, even for views. It is not a separate public input that the host page needs to set.

While a snapshot is active, the global configuration is retained. Closing the task or view removes analysisConfig and makes the global configuration active again. Updating the external config input also leaves the task or view and applies the new settings to the main network. Merely updating the host page's settings form does not have to change the plugin configuration.

A snapshot records the settings of a task or view; it does not guarantee that rerunning an analysis will produce identical results after the underlying databases have been updated. Host pages can listen to drugstone-analysis-config-change to display the settings currently used by the plugin, offer to adopt them, or restore their main-network settings afterwards. See Events for the payload and an integration example.
