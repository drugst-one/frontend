For now we depicted cases of information flow from the host page to the drugstone component ({{"<"}}drugst-one{{">"}}).
To communicate some information from Drugst.One to your host page, if requested, we emit events that can be listened to. This is generally achieved by adding an EventListener to the component: We select the component by its id (here 'drugstone-component-id') and add the necessary EventListener where '$eventName' has to be replaced with one of the events specified below. In this example we just want the received content to be printed into the browsers console, but this call may be replaced by any custom code, handling the event data.
In the following the specific events will be covered, including the necessary eventName to listen to, as well as how the result object is structured. Also some use-cases for the received object might be proposed here.

Active settings ('drugstone-analysis-config-change')

Drugst.One emits this CustomEvent when a task or view activates or updates its snapshot configuration, and when that configuration is removed on returning to the main network. The host page's global settings may differ from those of the snapshot. See Global configuration and snapshot settings for the distinction.

The event.detail payload contains:

  • version: the payload format version, currently 1.
  • source: task, view, or global. global reports the return to the main-network configuration.
  • config: a detached copy of the active configuration, not just the changed fields. The example below shows only a selection of its properties.

Database names use the plugin format, for example APID or OmniPath. licensedDatasets is a shared flag, not a separate license choice for each database. Normalize database names, defaults and available licensed/open variants before comparing the event configuration with your host-page settings.

Using the event in a host page
  • Show which settings the active task or view uses, or make the host settings form read-only while showing a saved snapshot.
  • If normalized settings differ, offer to adopt the snapshot settings in the host form. Update the form without writing config back to the plugin while the snapshot is open: an external config update closes the task or view.
  • On source: 'global', compare again. If snapshot settings were adopted, offer to restore the global settings or keep the adopted settings for the main network. Only write them back to the plugin when the user chooses to keep them.
  • Remember settings as browser preferences after an explicit user choice, rather than automatically saving every snapshot that is opened.

This event is a notification, not a command or a task-completion signal. It does not fire for every global config assignment, and it does not replay earlier events. Register your listener before opening a task or view. Repeated events can occur; compare settings instead of assuming each event represents a different task.

The event bubbles and is composed, so it can also be observed by an ancestor such as document. When embedding multiple plugins, listen directly on the intended drugst-one element. The event is not cancelable, and changing its copied payload does not change the plugin settings. Remove the listener with drugstone.removeEventListener('drugstone-analysis-config-change', onAnalysisConfigChange) when the host component is destroyed.
